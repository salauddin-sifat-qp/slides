1 · Engineering update workflowHow it works

So we made one command:
/weekly-update

  1. Shell scripts
    Fetch the numbers
    • total-users.sh
    • radar-bugs.sh
    • 500-errors.sh
    • query-perf.sh
    • run-tests.sh
  2. git + gh
    Find what shipped
    • Merged PRs since Saturday
    • In prod: Production
    • Only in master: Staging
    • Still open: In Progress
  3. The model
    Write it up
    • Drop lint and version-bump noise
    • Sort into Feat / Fixes / Engineering
    • Turn commits into plain sentences
  4. Scripts again
    Post to Slack
    • build-blocks.js builds the bullets
    • post-slack.sh sends it
    • Lands in #livepolls

Scripts fetch the numbers, the model only writes. No data means SKIPPED, never a guess.

2 · When to use AI, and when notHusky

Husky: every commit
goes through the gate.

Not AI
  1. git commit
    pre-commit
    • lint-staged, staged files only
    • eslint + oxfmt on .ts / .tsx
    • stylelint --fix on .css / .scss
  2. git commit
    commit-msg
    • commitlint, conventional commits
    • Bad format? The commit bounces.
  3. git push
    pre-push
    • Maps changed files to their tests
    • Runs only those

Staged files only: the repo still has ~26k old stylelint violations. We fix what we touch.

2 · When to use AI, and when notReliable AI code

Want reliable AI code? Give it a linter,
not a longer CLAUDE.md.

CLAUDE.md / skill file
## CSS
- Use design tokens.
- No hex colors.
- Keep property order.
A suggestion. Easy to lose in a long session.
stylelint.config.mjs
'color-no-hex': true,
'order/properties-order': [ … ],

$ git commit
✖ Unexpected hex color "#1b87e6"  color-no-hex
A rule. The commit fails, the AI reads the error and fixes it.

AI writes → lint fails → AI reads the error → AI fixes it → lint passes

3 · An idea of ours: LivePolls LibraryVector DB

Vector DB:
search by meaning.

It stores every chunk of the book as an embedding. Ask a question, and it returns the chunks closest in meaning.

Ctrl+F finds words. A vector DB finds meaning.

askhow do plants make food?
  • Ch 4 · Photosynthesis overview0.91
  • Ch 4 · Chlorophyll and light0.88
  • Ch 4 · Glucose and energy0.84
  • Ch 5 · Mitosis0.21
No word in common with "photosynthesis". Still the top hit.
3 · An idea of ours: LivePolls LibraryRAG

RAG: look it up,
then answer.

  1. R · Retrieve
    Find the chunks
    • Vector DB returns the chapter 4 chunks
  2. A · Augment
    Build the prompt
    • Only those chunks go to the model, not all 300 pages
  3. G · Generate
    Write the answer
    • Grounded in the book, not the model's memory

An open-book exam, not a memory test.

    Add to the Library

    • Fast, and different every time

4 · The importance of a system promptWhy have your own

Claude Code's prompt is
written for everyone.

Stock Claude Code
- General software engineering rules
- Tuned for the average user
- Tends to add "helpful" extras
Good default. Not your team's rules.
My system prompt · 176 lines
- Read the code before changing it
- Smallest correct change, nothing extra
- Verify once, at the end, then stop
- Short answers, no filler
Written once. Applied to every single message.

Works in Claude Code too: claude --append-system-prompt-file ./rules.md
