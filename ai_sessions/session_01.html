The Journey Begins

You open a CLI.
You type a message.

~/projects/api $ pi
▶ Why is this function returning null?
▸

Simple enough. But between that keystroke and the answer, something remarkable happens. Let’s follow it.

Step 1 · Tokenize

Tokens are the
currency of LLMs.

Not words. Not characters. Subword chunks — the unit of cost, memory, and everything the model processes.

Step 1 · Tokenize

Your text is split
into chunks.

“Why is this null?”
Split
“Why” “ is” “ this” “ null” “?”

Not words. Not characters. Subwords — from the model’s trained vocabulary of ~100k pieces.

Step 1 · Tokenize

Each chunk becomes
a number.

“Why is this null?”
Split
“Why” “ is” “ this” “ null” “?”
Encode
10445 374 420 1202 30

The model only ever sees integers. Text is gone from this point forward.

Step 1 · Tokenize

Every model has its
own vocabulary.

Claude, GPT-4, Gemini — same text, different token IDs. Each trained with its own dictionary. “null” might be token 1202 in one model and 4498 in another.

Larger vocabulary = bigger chunks = fewer tokens = cheaper and faster.

This is why costs differ between providers even for identical prompts.

Step 1 · Tokenize

Common is cheap.
Rare is expensive.

function
1 token — seen millions of times in training
fr aj b ous
4 tokens — Lewis Carroll invented it

JavaScript costs less than an obscure DSL. Your internal variable names cost more than plain English.

A parameter is a single floating-point number. A frontier model has hundreds of billions of them — GPT-4 is reported at ~1.8 trillion. They are the model’s entire knowledge — every fact, grammar rule, coding pattern — encoded as numbers.

Prompting never changes them. They are frozen after training.

Step 2 · Into the LLM

It read the internet.
And learned from
every mistake.

Trillions of tokens
→
Predict next token
→
Measure error
→
Nudge every parameter
→
Repeat

Backpropagation. Each of those 1.8 trillion numbers gets nudged a tiny amount after every wrong prediction. After 10 trillion examples, the model knows essentially everything it will ever know.

Step 2 · Into the LLM

Then humans
rated its answers.

01
Supervised Fine-Tuning
Human contractors wrote ideal Q&A examples. Model trained on those. Now it behaves like an assistant, not a text autocomplete.
02
Reward Model
Humans ranked multiple responses to the same prompt. A separate model learned to predict which answer humans prefer.
03
Reinforcement Learning
The LLM was adjusted to maximise the reward score. Helpful, honest, safe — not because programmed, because humans rated those higher.
Step 2 · Into the LLM

Every token looks at
every other token.

I deposited money at the bank ← financial institution
I sat by the river bank ← riverbank

Same word. Completely different meaning. Attention lets every token update its meaning based on surrounding context. This is the core mechanism of the transformer.

Step 2 · Into the LLM

Nobody programmed
reasoning.
It appeared.

At scale, the model began to reason, write code, translate languages, solve maths — none explicitly trained. Emergent behaviour from one objective: predict the next token.

Step 3 · Tool Call & Loop

Sometimes the model
needs to do something.

💬 Model decides it needs to read a file to answer tool call
⚙️ Harness executes — reads the file, runs bash, searches the web execute
↩️ Result injected back into the context window inject
🔁 Model runs again with new information — repeats until done loop

A raw API call does this once. An agent does this as many times as the task requires.

Step 4 · Thinking

Before answering,
it thinks.

Internal reasoning (hidden tokens)
“The function signature shows it returns a User object. Line 47 calls getUser() without a null check. If the database returns no record, getUser() returns null. The caller dereferences it directly. That’s the crash site.”
Visible response
“The null comes from getUser() on line 47. Add a null check before dereferencing or use optional chaining.”

“Think step by step” works because it activates token patterns associated with correct reasoning in the training data. The model has seen billions of examples of step-by-step reasoning leading to right answers.

Step 5 · Context

Fixed window.
Everything
competes for space.

System prompt + history + tools + files
← thinking room

Weights are what the model knows. Context is what it’s looking at right now. When the window fills, early context falls off silently — the model isn’t forgetting, it never had access to begin with.

Step 5 · Context

Every token in your prompt
is a token taken from thinking.

Bloated system prompts. Full files when only 10 lines matter. Long conversation history nobody trimmed. All of it eats the window.

The best prompts are the shortest ones that still communicate everything necessary. Not style — engineering.

Step 5 · Context

Engineer the model’s
behaviour through the prompt.

Ponytail Mode
Write the minimum code that works. No scaffolding, no speculative abstractions. Stop at the first rung that holds.
Caveman Mode
Terse prose. Short sentences. Answer first, explain only if asked. No padding, no preamble.

Less in → more room to think → better output. Every time.

Step 6 · Output

Token IDs.
Decoded back to text.
One at a time.

Output
2028 2523 374 1202
Decode
“The” “ issue” “ is” “ null”

Each token generated one at a time. That’s why responses stream. That’s why the model can’t take back what it already wrote.

What is an Agent Harness?

The scaffolding that turns a model into a tool
Agent Harness

A raw API call
is not an agent.

Text in, text out. One turn. No memory. No tools. No loop. A very smart autocomplete.

What a harness does

Loop + Context + Tools

System Prompt
Shapes persona, constraints, rules. Where ponytail/caveman live. The model's operating mode.
Tool Definitions
Declares what the model can call — read files, run bash, search the web, call APIs.
Loop Logic
Runs model → executes tool calls → feeds results back → repeats until done.
Context Injection
Puts the right information in the window — repo contents, docs, memory, file diffs.
Harness quality · In the wild

Same model.
Different harness.
Different output.

pi
Claude Code
Cursor
Copilot

All of these can run Claude under the hood. The harness determines context, tools, and how long it can work.

The model is the engine. The harness is the car.

The point

A good harness
changes the output
drastically.

Most people blame the model. The model is usually fine. The harness is the problem.

Our workflows

Same goal.
Two different stacks.

SifatTerminal-native
  • tmux
    Persistent sessions — agent in one pane, editor in another, always running.
  • pi primary
    My agent harness — custom skills, subagents, fast commands baked in.
  • Claude Code secondary
    Anthropic’s official CLI — for a second opinion and heavier autonomous runs.
  • neovim
    Terminal-native editor — zero context switch to reach the agent.
  • supermaven
    Inline autocomplete — fast, low-latency, stays out of the way.
KhairulIDE-native
  • Cursor primary
    AI-native IDE — inline edits and agent mode in one window.
  • Agent mode
    Multi-file changes with the loop running inside the editor.
  • Codebase index
    Semantic search over the repo feeds the model context automatically.
  • Tab autocomplete
    Cursor’s multi-line predictions as you type.

Different cars, often the same engine underneath — both can run the same model. The harness is the choice.
